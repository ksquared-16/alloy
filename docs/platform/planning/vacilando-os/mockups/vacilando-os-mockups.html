Reading this mockup. Every number, worker, and card is a projection of real toolkit state (~/.local/state/alloy-dev) — the app owns no parallel model. Each action (Answer, Approve Merge, Start New Sprint, Promote to Staging) maps to one entry in a fixed, fail-closed command allowlist that calls the existing alloy-* commands — consequential actions preview before they confirm, and release is never auto-approved.  ·  Desktop + mobile share one identity and one event stream.  ·  Full rationale in PRODUCT-REVIEW.md.
