# Assignment Platform — Operator workflow (canonical)

**Owner:** platform · **Status:** active · **Last reviewed:** 2026-07-25

Operators manage **Assignments**. Scheduling is a characteristic of an Assignment.

## Focus Panel — four states

1. **Children summary** — Compact primary Assignment scan (`Room · Days · Effective · Time`); quiet `+N more` when secondaries exist. Opens the Assignments list. Operator label: **Assignments** (not Schedule).
2. **Assignments list** — Primary first, then Secondary. Compact rows (type · program · room · days · time · effective · state · financial). **Day Timeline** for all assignments on this surface. Add / Edit / Duplicate / Make primary / Archive entry points. No intermediate schedule summary page.
3. **Single Assignment detail** — Calm white two-column property grid + Operational Effects · Financial Summary · History · Actions. Multi-assignment Timeline stays on the list.
4. **Edit / Create** — Shared editor. Add → Type → Program/Room/pattern/time/dates → save. Empty types deep-link to Assignments Workspace → Studio → Types (no seed/migrate dead end).

## Workspace

Work: **Overview · Roster · Attendance** (no separate Actions tab).  
Studio: **Types · Patterns · Validation** (Templates hidden until usable).

- Header: **Add Assignment** + Actions dropdown.
- Roster: selection + bulk Make primary / Archive via registered actions.
- Overview: assignment attention; Add Assignment sends operators to Roster for subject selection.

## Program / Room

See `assignment-platform-settings-inventory.md` §1b. Inquiry Program interest is editable until a committed Assignment exists; thereafter the primary Assignment owns operational Program/Room/schedule.

## Settings

Assignment Types authoring: Studio → Types. Inventory: `assignment-platform-settings-inventory.md`.
