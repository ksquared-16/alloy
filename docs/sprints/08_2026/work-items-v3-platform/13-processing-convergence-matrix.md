# Work Items V3 — Processing Convergence Decision Matrix

Slice 4 audit of Processing operator lanes vs Work Items execution layer.

Processing remains the **system of record**. Work Items is the **execution/discovery layer** — no duplicated state machines.

| Processing lane / state | Operator meaning | Work Item? | Slice 4 action |
| --- | --- | --- | --- |
| **Needs Review** | Case requires human review before handoff | **Yes** — projected row (`processing:{caseId}`) | **Implemented** — first convergence |
| Ready to Generate | Form draft can be generated | No (Processing-only workflow) | Deep-link only when case linked later |
| Ready to Publish | Generated form ready to publish | No | Processing-only |
| Needs Decision | Recommendation requires operator decision | Deferred | Deep-link; same projection pattern as Needs Review in a future slice |
| Exception / blocked | Case failed validation or handoff | Deferred | Processing-only until exception taxonomy is stable |
| Completed / Archived | Terminal states | No | Row removed from Work Items projection on refresh |

## Navigation contract

- Processing queue → select Needs Review case → **Open in Work Items** (future) or discover via Processing source filter.
- Work Items projected row → **Open in Processing** → `dispatchOpenProcessingCase`.
- Complete in Processing (approve) → `dispatchOperationalWorkRefresh` → Work Items queue + Processing warm cache refresh.

## Provenance

Projected rows show: **Generated by Processing → Case → Needs Review** (not generic category-only labels).

## Deferred convergence

- **Communications** — no operational_tasks bridge; source remains disabled.
- **Recurring** — no schedule runtime in V3; source disabled.
- **Scheduling / Billing / Attendance** — out of scope for V3 platform convergence.
