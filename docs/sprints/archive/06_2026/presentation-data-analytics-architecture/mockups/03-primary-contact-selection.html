Why a rule is required

A to-many relationship (Children) traversed to a scalar field (Current Room) is ambiguous — which child's room?

Without a selection rule, the reference is invalid. The rule becomes part of the Data Reference — so the value is unambiguous everywhere it's used.

When a to-many role resolves to a single value, Alloy forces an explicit choice. This prevents the silent "first row wins" ambiguity that plagues generic builders.
