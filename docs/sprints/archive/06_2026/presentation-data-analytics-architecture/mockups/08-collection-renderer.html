A collection renderer accepts Collection<Child> and declares a per-item template — each column is itself a Binding over the item's references, validated by the same renderer contracts.

Other collection renderers accept the same shape: List (primary/secondary line), Timeline (items with a Date), Relationship Card.
Collections reuse the same binding machinery, one level down — a collection is a surface-within-a-slot. Invoices, Tasks, Payments, Communications, Documents and Activities all bind the same way.
