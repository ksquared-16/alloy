# Forms Engine V1.1 — Usable Flow Sprint (May 2026)

---

## 1. Sprint objective

Make **Forms Engine V1** **operationally usable** end-to-end:

**Admin selects/sends a form → recipient completes it → submission persists → document can be generated/linked → workflow event is emitted → admin can review/act.**

This sprint extends the **completed V1 foundation** with **minimal admin APIs, embed fixes, and thin admin UI** — **not** an architecture redesign.

**Locked references:** `docs/sprints/05_2026/forms-engine-v1.txt` (V1 foundation, appendices, freeze rules).

---

## 2. Current status (post–Card 0 audit)

| Area | State |
|------|--------|
| **Backend foundation** | **Exists** — DB model, RLS, migrations, versioned schemas, signatures, junctions, stub PDF boundary. |
| **Admin APIs** | **Exists** — `/api/admin/forms/**` (definitions, versions, publish, submissions, submit, generate-document). |
| **Public APIs** | **Exists** — `/api/public/forms/[token]/**` (resolve, submissions, patch, submit). |
| **Public embed** | **Exists** — `/forms/embed/[token]` + `FormEmbedClient` + `FormEngineRenderer`. |
| **Admin UI** | **Missing** — no `app/admin/forms` surfaces; ops rely on APIs or DB. |
| **Public-link admin API** | **Missing** — `form_public_links` rows require manual/SQL; design doc described CRUD not yet implemented. |
| **Medication demo** | **Blocked in embed** — select/multiselect require `option_values_by_field_id` on submit; embed does not hydrate/pass options. |
| **Submission review** | **API-only** — `GET .../submissions` and `GET .../submissions/[id]` work; no staff UI. |
| **Workflow** | **Events emitted** (`form_submitted`, `form_signed`, `form_document_generated`) into **`workflow_events`**; operational surfacing (workflows consuming events, admin visibility) is **follow-up** unless scoped here. |

## 4. Anti-drift rules

- **Forms do not own CRM identity.** Use **person-first helpers** (`applyFormLeadCaptureIntake`, booking-native person/customer flows); submissions store FKs only.  
- **Forms do not own documents.** Generated/signature assets are **`documents`** rows + **`form_submission_documents`**; reuse Storage, RLS, and admin document patterns.  
- **Forms do not own workflow execution.** Emit **`workflow_events`** via **`emitEvent`** only; no parallel bus; workflow **runs** remain the existing **`workflow_runs`** / editor model.  
- **Submissions may reference** entities, documents, and events; they **must not replace** those systems.  
- **Public links are access tokens**, not user accounts; hash-at-rest; plaintext shown only when issued (create/rotate).  
- **Admin UI is thin operational UI** — not a drag/drop builder, not a second schema designer.

**Explicit non-goals:** duplicate CRM or documents tables; DocuSign; full PDF engine rewrite; field_values auto-sync; generic form builder.

## 5. Definition of done (sprint)

- [ ] **Medication authorization demo** completable **end-to-end** via public embed (submit succeeds with selects).  
- [ ] Admin can **create/copy a public form link without SQL** (Card 1 API; Card 3 consumes it).  
- [ ] Admin can **view submissions without raw DB access** (Card 3 + Card 4).  
- [ ] Admin can **generate or access** a document from a submission (existing generate-document API + documents linkage; UI entry in Card 4).  
- [ ] **Workflow events** continue to emit through existing **`workflow_events`** (no regression).  
- [ ] **Existing tests pass** (`tsc`, forms + admin + public forms test suites as in CI / dev convention).
