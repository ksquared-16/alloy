# Control-plane durability incident — two governed push requests, one vanished and one malformed

Recorded per the instruction's §1: *"If a governed request disappears again, record the control-plane
durability incident and re-file normally. Do not rewrite product work because a request vanished."*

No product work was changed in response to any of this.

## What happened

| request | action | outcome |
|---|---|---|
| `gar_a29f28ec557671` | `repository.push` | filed and acknowledged with an id; later **`no such request`** |
| `gar_9c4b117afe5137` | `repository.push` | failed **`missing_repository — repository is required`**; never composed by this lane |
| `gar_f0316be4fa0942` | `promotion.open_pr` | failed **`head_drift`** — a *consequence* of the push never landing |
| `gar_fa36930f422e9e` | `repository.push` | refiled; **Succeeded**, `5d6d27405` on the remote |

Two things are notable and neither is explicable from this lane:

1. **`gar_a29f28ec557671` was acknowledged and then did not exist.** The CLI printed
   `Governed action filed / gar_a29f28ec557671 / Status: Requested`, and a later
   `--status gar_a29f28ec557671` answered `no such request`. It never executed and never failed.

2. **`gar_9c4b117afe5137` failed `missing_repository`, and this lane never composed it.** Every push
   payload here is generated by `file-push-request.sh`, which always sets
   `repository: "ksquared-16/alloy"` — the generator cannot emit a payload without it. The id does
   not match any request this lane filed.

The `head_drift` on the PR was not an independent failure: the PR pinned a head the push had not
delivered, because the push had silently gone missing.

## Why it matters beyond this run

`head_drift` reads like a lane mistake — a stale head, a bad base. Here it was downstream of a
vanished request. A worker that treats `head_drift` as its own error will re-derive the branch state
it already had correctly, and may "fix" product work that was never wrong. The tell is cheap:
**check that the push request still exists before trusting the failure of anything that depended on
it.**

## Handling

Refiled the push normally; it succeeded. No product change, no payload change, no rebase.
